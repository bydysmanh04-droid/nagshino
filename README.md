# نقشینو

«هر روز ۱۰ دقیقه، یک قدم به هنرمند شدن نزدیک‌تر شو!»

نقشینو یک اپ نصب‌شدنی (PWA) برای یاد گرفتن طراحی با مداد است. این پوشه کل پروژه است.
نیازی به برنامه‌نویسی نداری؛ هر جا لازم بود تغییری بدهی، در همین راهنما قدم‌به‌قدم نوشته شده.

---

## ۱. معرفی پروژه و پوشه‌ها

| فایل یا پوشه | چیست؟ |
|---|---|
| `index.html` | صفحه‌ی اصلی اپ (فقط یک قاب خالی که کدها پر می‌کنند) |
| `style.css` | ظاهر اپ: رنگ‌ها، اندازه‌ها، انیمیشن‌ها |
| `app.js` | کار اپ: صفحه‌ها، تایمر، موردعلاقه‌ها، پیشرفت |
| `manifest.json` | اطلاعاتی که اپ را نصب‌شدنی می‌کند (نام، رنگ، آیکون) |
| `service-worker.js` | آفلاین کار کردن اپ و رسیدن تغییرات به کاربران |
| `data/` | محتوای اپ در سه فایل JSON (تمرین‌ها، موضوع‌ها، متن‌های ثابت) |
| `fonts/` | محل فایل فونت (فعلاً خالی است) |
| `icons/` | آیکون اپ در اندازه‌های ۱۹۲، ۵۱۲ و maskable |
| `images/` | تصاویر تمرین‌ها (فعلاً خالی است) |
| `design/` | رنگ‌ها، «پرامپت طراحی» و فهرست تصاویر با پرامپت ساخت آن‌ها |

**نکات مهم:**
- اپ بدون سرور است و هیچ چیزی از اینترنت بارگذاری نمی‌کند (نه فونت، نه کتابخانه). همه‌چیز داخل همین پوشه است.
- **موردعلاقه‌ها و تمرین‌های انجام‌شده** فقط روی همان گوشی ذخیره می‌شوند و به گوشی دیگر منتقل نمی‌شوند. اگر کاربر اپ را حذف کند یا اطلاعات مرورگر را پاک کند، این‌ها هم پاک می‌شوند.
- **تایمر** فقط وقتی اپ باز است کار می‌کند و در پایان پیام و صدای کوتاه نشان می‌دهد. اپ بدون سرور نمی‌تواند وقتی بسته است اعلان بفرستد.
- **تمرین روز** بر اساس تاریخ انتخاب می‌شود. هر روز یک تمرین عوض می‌شود و برای همه یکسان است.

---

## ۲. انتشار رایگان (گرفتن لینک)

اپ باید یک بار منتشر شود تا لینک داشته باشد.

**⚠️ چند نکته‌ی خیلی مهم:**
- اپ فقط روی لینک امن (که با `https` شروع می‌شود) درست کار می‌کند. فایل `index.html` را **با دو بار کلیک روی کامپیوتر باز نکن**، چون در آن حالت حالت آفلاین و بارگذاری فایل‌های JSON درست کار نمی‌کند (اپ همین را با یک پیام به تو می‌گوید). برای دیدن اپ از لینک منتشرشده استفاده کن.
- برای اینکه سایت پاک نشود و بتوانی بعداً به‌روزش کنی، آن را به یک **حساب رایگان خودت** وصل کن.
- **لینک اپ باید همیشه ثابت بماند.** برای به‌روزرسانی، پروژه‌ی جدید را روی **همان سایت** منتشر کن، نه اینکه سایت تازه بسازی. چون با عوض شدن لینک، کسانی که اپ را نصب کرده‌اند به‌روز نمی‌شوند.
- این مراحل را قبل از اقدام از سایت رسمی سرویس هم نگاه کن، چون ممکن است ظاهر یا مراحلشان عوض شده باشد.

### راه اول: Netlify (ساده‌تر برای شروع)
1. در سایت `netlify.com` یک حساب رایگان بساز (و وارد شو).
2. وارد بخش ساخت سایت (Add new site / Deploy manually، یا همان Netlify Drop) شو.
3. **کل پوشه‌ی پروژه** را (نه فایل ZIP) داخل کادر بکش و رها کن. اگر فقط ZIP داری، اول آن را از حالت فشرده دربیاور.
4. بعد از چند ثانیه یک لینک می‌دهد. می‌توانی اسم لینک را در تنظیمات سایت (Site settings) به چیزی خوانا تغییر بدهی و آن اسم را دیگر عوض نکنی.
5. حتماً سایت را به حساب خودت وصل (claim) کن تا بعد از مدتی پاک نشود.

### راه دوم: GitHub Pages
1. در `github.com` یک حساب رایگان بساز.
2. یک مخزن (repository) عمومی جدید بساز.
3. همه‌ی فایل‌های پروژه را داخل آن آپلود کن (Add file ← Upload files).
4. در Settings ← Pages، شاخه‌ی `main` و پوشه‌ی `/ (root)` را انتخاب کن.
5. بعد از چند دقیقه لینک اپ به شکل `https://اسم-تو.github.io/اسم-مخزن/` ساخته می‌شود.

(اپ طوری ساخته شده که روی هر دو سرویس درست کار کند، حتی وقتی در یک زیرمسیر باز می‌شود.)

## ۳. نصب روی گوشی

**اندروید (Chrome):**
1. لینک اپ را در Chrome باز کن.
2. روی سه نقطه‌ی بالا بزن.
3. «Add to Home screen» یا «Install app» را انتخاب کن و تأیید کن.

**آیفون (Safari):**
1. لینک اپ را حتماً در **Safari** باز کن.
2. روی دکمه‌ی اشتراک‌گذاری (مربع با فلش رو به بالا) بزن.
3. «Add to Home Screen» را انتخاب کن و تأیید کن.

---

## ۴. چک‌لیست تست قبل از دادن به دیگران

قبل از اینکه اپ را به کسی بدهی، این‌ها را روی گوشی خودت انجام بده:

- [ ] لینک را روی گوشی باز کن و ببین همه‌ی صفحه‌ها درست باز می‌شوند.
- [ ] اپ را نصب کن (Add to Home Screen).
- [ ] اینترنت گوشی را قطع کن (حالت هواپیما) و اپ را از آیکونش باز کن. باید آفلاین هم باز شود.
- [ ] یک تمرین را موردعلاقه کن و «انجام شد» بزن و در صفحه‌ی «پیشرفت من» ببین.
- [ ] تایمر را روشن کن و ببین درست کار می‌کند.
- [ ] یک تغییر کوچک بده (مثلاً عنوان یک تمرین)، `CACHE_VERSION` را بالا ببر، دوباره منتشر کن، اینترنت را وصل کن و اپ را یک بار ببند و باز کن. باید نوار «نسخه‌ی جدید آماده است» بیاید.

## ۵. چطور محتوا یا تمرین جدید اضافه کنم و برای همه به‌روز شود؟

همه‌ی تمرین‌ها در فایل `data/exercises.json` هستند. این یک نمونه‌ی واقعی از یک تمرین است:

```json
{
  "id": "ex-011",
  "title": "گل لاله",
  "category": "objects",
  "level": "easy",
  "isChallenge": false,
  "durationMin": 10,
  "description": "یک گل لاله‌ی ساده با چند خط نرم بکش.",
  "finalImage": "images/ex-011-step-4.webp",
  "steps": [
    { "text": "یک بیضی کوچک و عمودی برای گل بکش.", "image": "images/ex-011-step-1.webp" },
    { "text": "دو برگ تیز بالای ساقه اضافه کن.", "image": "images/ex-011-step-2.webp" },
    { "text": "ساقه‌ی بلند را به پایین بکش.", "image": "images/ex-011-step-3.webp" },
    { "text": "سایه‌ی نرم به گلبرگ‌ها و برگ‌ها بزن.", "image": "images/ex-011-step-4.webp" }
  ]
}
```

**معنی فیلدها:**
- `id`: شناسه‌ی یکتا. هر تمرین یک شناسه‌ی متفاوت دارد و **بعد از انتشار هیچ‌وقت عوضش نکن**، چون موردعلاقه‌ها و تمرین‌های «انجام‌شده» با همین شناسه روی گوشی کاربر ذخیره شده‌اند.
- `category`: یکی از شناسه‌های موضوع در `data/categories.json` (`animals`، `objects`، `shading`، `perspective`، `people`).
- `level`: `easy` (آسان)، `medium` (متوسط) یا `hard` (سخت).
- `isChallenge`: اگر `true` باشد، تمرین در بخش «چالش‌های پیشرفته» هم نشان داده می‌شود.
- `durationMin`: مدت زمان به دقیقه. تایمر همین مقدار را نشان می‌دهد.

**مراحل اضافه کردن تمرین جدید:**
1. فایل `data/exercises.json` را با یک ویرایشگر متن (مثلاً Notepad) باز کن.
2. تمرین جدید را مثل نمونه‌ی بالا کپی کن و بعد از آخرین تمرین بگذار. **بین تمرین‌ها باید ویرگول باشد** (و بعد از آخرین تمرین ویرگول نباشد).
3. عکس‌هایش را با همان اسم‌ها داخل پوشه‌ی `images` بگذار.
4. در `service-worker.js` عدد `CACHE_VERSION` را یکی بالا ببر (مثلاً `"v1"` را بکن `"v2"`).
5. پروژه را دوباره روی **همان سایت** منتشر کن (در Netlify: Deploys ← drag and drop کل پوشه).
6. کاربران بعد از اینکه یک بار اپ را با اینترنت باز کنند، نوار «نسخه‌ی جدید آماده است» را می‌بینند. با زدن «به‌روزرسانی»، اپ تازه می‌شود. بدون نصب دوباره.

**اگر فایل JSON را اشتباه ویرایش کنی** (مثلاً ویرگول جا بیفتد)، اپ پیام خطا نشان می‌دهد. برای پیدا کردن اشتباه می‌توانی متن فایل را در سایت `jsonlint.com` بچسبانی. اگر شک داشتی، نسخه‌ی قبلی را برگردان.

### اضافه کردن تصاویر ۱۰ تمرین اولیه
تا وقتی عکسی نباشد، اپ به‌جای آن یک جای خالی دوستانه با پیام «تصویر به‌زودی اضافه می‌شود» نشان می‌دهد و درست کار می‌کند.
1. فهرست کامل تصاویر (۴ تصویر برای هر تمرین، یعنی ۴۰ تصویر) و پرامپت ساخت هرکدام در `design/image-list.md` است.
2. هر تصویر را با همان اسم ذخیره کن و داخل پوشه‌ی `images` بگذار. اسم‌ها به این شکل‌اند: `ex-001-step-1` تا `ex-001-step-4`، و همین‌طور تا `ex-010-step-4`. تصویر مرحله‌ی ۴ هر تمرین همان تصویر نهایی است که در کارت‌ها دیده می‌شود.
3. پسوند فایل `.webp`، `.jpg` یا `.png` هر کدام باشد، اپ پیدایش می‌کند. نیازی به عوض کردن JSON نیست.
4. حجم هر تصویر ترجیحاً کمتر از ۲۰۰ کیلوبایت باشد تا اپ سریع بماند. اگر بیشتر بود، با یک سایت فشرده‌ساز عکس (مثل squoosh.app) کوچکش کن.
5. `CACHE_VERSION` را بالا ببر و دوباره روی **همان سایت** منتشر کن.

### عوض کردن رنگ‌ها
در فایل `style.css` در بخش `:root` (بالای فایل) همه‌ی رنگ‌ها با کد HEX نوشته شده‌اند. کد را عوض کن. اگر رنگ اصلی یا پس‌زمینه را عوض کردی، در `manifest.json` هم `theme_color` و `background_color` و در `index.html` هم `theme-color` را عوض کن. بعد `CACHE_VERSION` را بالا ببر.

### اضافه کردن فونت دلخواه (مثلاً وزیرمتن)
۱. فایل فونت را از **سایت رسمی خود فونت** دانلود کن (مثلاً صفحه‌ی گیت‌هاب وزیرمتن). قبل از آن، مجوز استفاده‌ی رایگان از آن را در همان صفحه ببین. وزیرمتن مجوز آزاد SIL Open Font License دارد.
۲. فرمت `woff2` بهترین است (`ttf` و `otf` هم قبول است). سه وزن Regular، Medium و Bold کافی است.
۳. فایل‌ها را داخل پوشه‌ی `fonts` بگذار.
۴. در `style.css` بخش توضیح‌داده‌شده‌ی `@font-face` (بالای فایل) را فعال کن. یعنی علامت شروع و پایان کامنت را بردار و اسم فایل‌ها را با اسم فایل‌های خودت یکی کن. بعد در `:root`، خط `--font` را همان‌طور که در توضیح آمده تغییر بده.
۵. اسم فایل‌ها را در `service-worker.js` در بخش `FONT_FILES` هم اضافه کن تا آفلاین هم کار کنند.
۶. `CACHE_VERSION` را بالا ببر و دوباره منتشر کن.

## ۶. ساخت فایل APK برای نصب مستقیم روی اندروید (بدون فروشگاه)

با APK می‌توانی فایل نصبی را مستقیم (مثلاً با تلگرام) برای دیگران بفرستی. این کار فقط برای اندروید است.

> توجه: من (Claude) فایل APK را نساخته‌ام. فقط پروژه‌ی PWA و همین راهنما آماده شده است. خودت با سایت زیر APK را می‌سازی.

**قبل از شروع:** اپ را منتشر کن و لینک ثابت داشته باش (بخش ۲). APK به همان لینک وصل می‌شود.

### مراحل ساخت با PWABuilder
1. وارد `pwabuilder.com` شو.
2. لینک اپ را داخل کادر بنویس و Start را بزن. سایت اپ را بررسی می‌کند. اگر manifest و service worker را تأیید کرد، ادامه بده.
3. روی Package for stores بزن و Android را انتخاب کن.
4. گزینه‌ها را مثل پیش‌فرض بگذار. اگر سایت درباره‌ی نوع بسته پرسید، نسخه‌ای را انتخاب کن که برای نصب مستقیم (بدون Google Play) مناسب است. اگر مطمئن نشدی، به توضیحات خود سایت نگاه کن چون ممکن است عوض شده باشد.
5. Download را بزن. یک فایل ZIP می‌گیری که داخلش فایل `.apk` و فایل Keystore و یک فایل رمز است.

### نگه داشتن Keystore و رمزش (خیلی مهم)
- فایل **Keystore** (پسوند `.keystore` یا `.jks`) و **رمزش** مثل کلید خانه‌اند. برای هر به‌روزرسانی APK در آینده لازم‌اند. اگر گمشان کنی، دیگر نمی‌توانی APK به‌روزشده‌ای بسازی که روی APK قبلی نصب شود.
- یک نسخه را در جایی امن نگه دار (مثلاً حافظه‌ی USB و ایمیل خودت) و رمز را جدا از فایل یادداشت کن.
- یک نسخه‌ی پشتیبان از **کل پوشه‌ی پروژه** هم بگیر.
- فایل Keystore و رمز را برای هیچ‌کس نفرست.

### فرستادن APK برای دیگران
فایل `.apk` را مثل هر فایل دیگری از راه تلگرام یا واتساپ بفرست، یا آن را جایی آپلود کن و لینک دانلود بده.

### نصب توسط گیرنده
1. فایل APK را روی گوشی دانلود کند و روی آن بزند.
2. اگر گوشی پیام داد که نصب از این منبع مجاز نیست، گزینه‌ی «نصب از منابع ناشناس» (Install unknown apps) را برای همان برنامه‌ی دانلودکننده (مثلاً تلگرام یا Chrome) فعال کند. اسم این گزینه در گوشی‌های مختلف کمی فرق دارد.
3. دوباره روی فایل بزند و نصب را تأیید کند.

### آیفون
آیفون فایل نصبی ندارد. کاربران آیفون فقط با «Add to Home Screen» از Safari نصب می‌کنند (بخش ۳).

### چه تغییری APK جدید می‌خواهد؟
- **تغییر محتوا، رنگ و فونت: APK جدید لازم نیست.** فقط پروژه را روی همان سایت دوباره منتشر کن (بخش ۵) و کاربران به‌روز می‌شوند.
- **تغییر نام اپ یا آیکون اپ روی گوشی: به APK جدید نیاز دارد** (و برای ساخت آن از همان Keystore قبلی استفاده کن).
